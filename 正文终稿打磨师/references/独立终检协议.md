# 独立终检协议（读者视角 + 商业化视角 + 知识边界）

> 版本：V1.0 | 归属：正文终稿打磨师（本技能内置，不依赖任何外部审稿技能）
> 来源：内化自原审稿技能的 reader-agent（6 维度）与 commercial-agent（7 维度）及第5关知识边界检查，已去除 Agent spawn 依赖，由本技能主线程直接执行。
> 触发方式：**可选终检**。用户要求 `/final_check`、卷末/全书完成、或打磨报告判定"质量存疑需上市前评估"时执行。不进每章默认流程。
> 执行方式：主线程加载本协议，对终稿做一次通读式终检（非逐字精修）。输出 Findings JSON（字段与本技能 findings 体系对齐：severity/category/location/evidence/issue/fix）。

---

## 一、读者视角终检（6 维度，权重合计 100%）

以"番茄小说碎片时间手机读者"心智执行：读前三段能否代入？每 200 字会不会想划走？读完记没记住东西？哪个瞬间出戏？

| 维度 | 权重 | 检查点 | 判定锚点 |
|------|:----:|--------|---------|
| D1 代入感 | 20% | 前 500 字视角锁定速度？内心独白是否"换我也会这么想"？关键场景有无读者能同频的物理细节（疼/冷/累/饿）？ | ≥80 分=完全进入主角视角；60-79=偶尔跳出；<60=全程旁观 |
| D2 节奏感 | 15% | 是否存在连续 500 字以上"想跳过"的低谷段？紧张/缓冲是否交替？每 200 字有无新信息？ | ≥80=一口气读完；60-79=偶尔走神；<60=多次想弃 |
| D3 角色辨识度 | 15% | 遮名测试：去掉"XX说"后能否区分说话人？（句长/用词/语气/口癖） | ≥80=90% 可辨认；60-79=主角可辨配角趋同；<60=分不清谁是谁 |
| D4 情绪共鸣 | 20% | 全章有无"心头一紧/笑出声/眼眶发热"的瞬间？情绪爆发前有无蓄力？反应是否符合"换我也这样"？ | ≥80=至少 2 次明显波动；60-79=偶有触动；<60=全程无感 |
| D5 悬念期待 | 15% | 章末最后一句是否构成"然后呢"的驱动力？悬念有无前文铺垫？期待是具体还是模糊？ | ≥80=强烈想追下一章；60-79=有点好奇；<60=无追更欲望 |
| D6 阅读流畅度 | 15% | 有无"这不对吧""太假了"的出戏点？有无需回读才能理解的句子？有无突兀逻辑跳跃？ | ≥80=全程顺畅；60-79=1-2 处轻微卡顿；<60=多处出戏 |

## 二、商业化视角终检（7 维度，权重合计 100%）

以"网文平台商业编辑"心智执行：这章发出去数据会不会难看？每个结论回答"这个改动能让数据提升几个点"。

| 维度 | 权重 | 检查点 | 判定锚点 |
|------|:----:|--------|---------|
| C1 开篇吸引力 | 20% | 首句有无反常/危机/悬念？前 100 字是否知道"主角是谁、想要什么、面临什么"？前 300 字是否出现冲突？ | ≥80=首句抓人、300 字已建冲突；60-79=有信息冲突不强；<60=全铺垫，大概率弃文 |
| C2 章末钩子 | 20% | 章末是否用有效钩子（悬念/反转/危机/期待/揭秘）？是否连续 3 章同型钩子？钩子是否在最后 1-2 句引爆？ | ≥80=强钩子；60-79=有钩子力度一般；<60=无钩子或软钩子 |
| C3 爽点密度 | 15% | 全章爽点数量与类型（打脸/逆袭/揭秘/获得/升级/反杀）？密度是否符合题材特征（都市爽文每千字≥1，慢热玄幻每 2000 字 1）？分布是否均匀？前文铺垫是否兑现？ | ≥80=密度达标且均匀；60-79=密度不足或分布不均；<60=全章无爽点 |
| C4 信息投放节奏 | 10% | 设定是否通过情节自然带出？单次设定释放是否 ≤200 字？有无"读者知道角色不知道"的信息差？ | ≥80=自然融入无负担；60-79=1-2 处说明文倾向；<60=大段设定轰炸 |
| C5 对标差异化 | 10% | 本作题材赛道定位？有无"别人没写过/没写好"的独特点？有无高同质化套路元素？ | ≥80=有明确差异化卖点；60-79=有意识不突出；<60=高度同质化 |
| C6 节奏控制 | 15% | 本章属高压推进还是低压关系章，节奏定位是否正确？有无可压缩冗余段？关键转折铺垫是否充足？ | ≥80=节奏精准；60-79=局部问题；<60=明显拖沓或仓促 |
| C7 完读率预判 | 10% | 综合前 6 维度预判本章完读率（高/中/低）？读者最可能在哪个位置退出（前 300 字/中段/章末）？4000 字体量是否适合碎片阅读？ | ≥80=无高危弃读段；60-79=1-2 处风险；<60=多处高危段 |

## 三、知识边界终检（第5关 LLM 层补充）

> 说明：数值/战力/生死/时间线等确定性检查由 `scripts/check-consistency.js` 覆盖（脚本层）。本节只做脚本无法覆盖的**知识边界**与**信息差**抽样，对照设定 JSON 的 `[角色知识边界]` 字段或衔接包。

1. 随机抽取 3 个信息差场景，核对角色是否说了"不该知道"的信息（知识越界）。
2. 角色对某秘密的反应，前文是否有信息传递场景支撑？
3. 角色表现与衔接包 `[角色知识边界]` 不符 = blocking 级，禁止定稿。
4. 信息差解除时机是否合理（过早揭晓=浪费钩子，过晚=读者遗忘）？

## 四、多平台 rubric（终检评分时按目标平台加载）

| 平台 | 核心评分维度 | 权重侧重 |
|------|------------|---------|
| 番茄小说 | 强开局、强冲突、高频爽点、低理解门槛 | 爽点 30% + 节奏 20% + 钩子 20% + 代入 15% + 文笔 15% |
| 起点中文网 | 设定自洽、升级路径清晰、长线期待 | 设定 30% + 结构 25% + 爽点 20% + 文笔 15% + 钩子 10% |
| 知乎盐言 | 钩子密集、反转密度高、情绪兑现快 | 反转 30% + 钩子 25% + 情绪 25% + 文笔 20% |
| 通用网文 | 综合评估，各维度均衡 | 均等分配 |

**番茄特供检查点**（目标平台=番茄时额外执行）：
1. 黄金三章：前 3 章是否在 3000 字内完成"建人设→制造冲突→给爽点"三步？
2. 爽点密度：每 2000 字至少一个情绪反馈点（爽/笑/紧张/泪）。
3. 低理解门槛：核心设定能否一句话说清？前 500 字能否理解主角处境？
4. 追读钩子：章末是否留"不点下一章就难受"的钩子？连续 3 章钩子类型不重复？
5. 张弛定位：高压章配齐钩子+爽点+悬念；低压章允许弱钩子，但每章给一个往下看的理由。

## 五、输出格式（Findings JSON，与终稿打磨师 findings 体系一致）

```json
{
  "check": "final_check",
  "chapter_id": "Ch.X",
  "platform": "番茄小说",
  "reader_score": 75,
  "commercial_score": 68,
  "findings": [
    {
      "severity": "blocking",
      "category": "commercial",
      "location": "Ch.X 章末",
      "evidence": "章末以'夜深了，他睡了'收尾",
      "issue": "C2 章末钩子缺失：无翻页动力，追读率将下滑",
      "fix": "改为悬念钩子：'他不知道，那封信已被别人拆开'"
    },
    {
      "severity": "advisory",
      "category": "character",
      "location": "Ch.X L50-70",
      "evidence": "（张三李四对话段落）",
      "issue": "D3 角色辨识度不足：遮名后无法区分说话人",
      "fix": "张三加口癖'说实话'，李四用短句+大白话"
    }
  ],
  "summary": "商业化钩子存在 blocking 问题，读者代入感达标。修复钩子后可定稿。"
}
```

**severity 定义**（与 Gate 体系一致）：
- `blocking`：必须修复，不修复不定稿（对应维度 <60）
- `advisory`：建议优化（对应维度 60-79）
- `info`：锦上添花（对应维度 80-89）

## 六、终检执行流程

1. **确认平台**：目标平台未知 → 使用通用 rubric。
2. **读者视角通读**：按 D1-D6 逐维度给分 + 标记出戏点（不必逐句，通读时标记）。
3. **商业化视角通读**：按 C1-C7 逐维度给分 + 标记数据风险点。
4. **知识边界抽样**：对照设定 JSON 抽 3 个信息差场景核查。
5. **汇总评分**：reader_score = 六维度加权；commercial_score = 七维度加权（按平台 rubric 调整权重）。
6. **输出 Findings JSON**：blocking 归零后才可定稿；advisory 列在打磨报告的 [需复核] 区供作者裁决。
7. **终检不重复修改**：终检只报告；发现的问题如果属于 Gate/质感范畴，回到对应通道修复；属于读者/商业维度的问题，直接给出 fix 由作者确认后改。

> 与默认打磨的关系：默认打磨（快速/深度通道）保证"技术合格"；独立终检保证"市场合格"。二者独立，终检是可选的上市前最后一道闸。
