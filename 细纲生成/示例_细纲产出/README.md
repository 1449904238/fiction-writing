# 示例_细纲产出 —— 细纲生成 Skill 的「一卷两文件」交付示例

本目录演示「细纲生成（02a）」在 **V6.1.1 卷文件聚合** 下的最终交付形态：一卷的内容收敛为**两个文件**，取代此前"每章细纲+衔接包+delta"的大量零散文件。供对照产出结构、校验格式是否符合 `SKILL.md` 的 **G.5b 卷聚合** 约定（上游做法一致：`小说设定架构师/示例_设定包/`、`小说大纲构建师/示例_大纲产出/`）。

## 组成

| 文件 | 作用 |
|---|---|
| `卷V-01_细纲与衔接.md` | **人读聚合**：本卷细纲 + 衔接包，各章以【CH-XXXX】锚点分隔（本示例含 CH-0001 一章） |
| `卷V-01_delta.json` | **机读增量**：`chapters[]` 聚合本卷各章 delta（本示例含 CH-0001 一章） |

> 单章的 `CH-XXXX_细纲.md` / `CH-XXXX_衔接包.md` 在本目录**不保留**——其内容已完整囊括进聚合文件；单章形态仅作为聚合脚本的**中间输入**存在，不再单独交付。delta 的逐章校验仍走 `merge-delta.js` 对 `chapter_delta_ChX.json` 的契约（聚合不动它）。

## 输入与本例说明

- **输入上游**：`小说大纲构建师/示例_大纲产出/`（《雾港档案》悬疑题材分卷大纲，CH-0001~0003）+ `小说设定架构师/示例_设定包/`
- **本示例聚焦 CH-0001**（V01 第 1 章，rhythm_function=开局高能矛盾）
- **题材**：mystery（悬疑）。按题材映射表必加载 方法论综合.md 的 M.1 第 9 条（悬疑灵异）+ 第 13 条（推理侦探）
- **网感方向**：悬疑=封锁题材 → 章节意图不做 `net_slang_scene` 标记（对齐 05 Gate 17 封锁题材跳过检测）

## 如何生成（aggregate-volume.js）

```bash
# 在 skill 根目录运行：把一卷内逐章产物聚合为两个卷级文件
node scripts/aggregate-volume.js --volume=V-01 --out=示例_细纲产出/卷V-01 --write \
  --dir="示例_细纲产出/*_细纲.md" --dir="示例_细纲产出/*_衔接包.md"
```

- 默认 dry-run 只打印摘要；`--write` 才写文件；`--json` 输出 JSON 摘要
- 卷目录与文件命名：`细纲/卷<卷号>/卷<卷号>_细纲与衔接.md` + `卷<卷号>_delta.json`

## 如何校验 / 对照

1. **聚合完整性**：对照 `SKILL.md` Part 6.1/6.2 与 G.5b，确认聚合 md 各章【CH-XXXX】单元完整、delta `chapters[]` 字段齐全
2. **卷 delta 机读**：本示例的 `卷V-01_delta.json` 已含 CH-0001 完整增量（角色状态/数值锚点/伏笔ops/知识边界），可作下游状态投影基准
3. **悬疑约束自查**：对照公式第 9/13 条——线索分层释放、每次接近真相付出代价、线索公平（例：顾衍当众调档的越权→内务记录在案=代价）

## 对照要点

- **一卷两文件**：人读聚合（通读/归档）+ 机读增量（状态投影）各司其职
- **最小侵入**：聚合不触碰单章校验（merge-delta/compress-handoff 逐章契约不变）；单章文件是脚本中间输入，非最终交付
- **自包含**：聚合文件字段填充 CH-0001 真实内容，非占位符；悬疑品类示范——信息释放慢、每次回报伴随代价
