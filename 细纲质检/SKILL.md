## 技能定位（独立质检器）

**本技能是一个自包含、独立的细纲质检模块。** 它不依赖任何上游生成流程（细纲怎么来的无所谓），也不向下游交付任何流程（质检完之后如何扩写无所谓）。**唯一的输入是逐章细纲文本，唯一的目标是输出一份质检报告。**

```
输入（可选提供，越多越准）：
├─ 逐章细纲：每章的目标情绪/核心冲突/场景/钩子/字数预算
├─ 衔接包字段：角色当前状态/禁止矛盾/数值锁定/角色知识边界/...
├─ 伏笔追踪表（如有）
└─ 设定元数据：题材 genre / 平台 platform / 数值锚点 number_anchors / 战力体系 power_system

约定：若某项输入缺失，对应检查项标"?信息不足"，进入"人工复核"档位，不默认通过。

输出（唯一交付物）：
└─ 质检报告：逐项检查结果(✅/⚠️/❌/?) + 证据链 + 综合评分(0-100) + 结论(放行/返工/重写)
```

**如何使用**：把要质检的细纲文本贴进来（或指明其文件路径），本技能即按下列 Part O5→Part 10 顺序执行检测，最终产出报告。**不从流程前面取任何东西，也不为流程后面准备任何东西。**

> **独立运行边界（V6.1.1 — 明确可独立项与可选深化项）**
> - ✅ **核心检测（仅需细纲文本即可运行）**：大纲五检 / 质量Gate①-④⑥⑦⑧⑨⑩ / 衔接包P0/P1自检（细纲内字段）/ 详细度检查与衰减 / 结构多样性 / 题材→钩子匹配 / 平台适配。
> - ⚠️ **深化检测（依赖额外输入；输入缺失一律"?信息不足→人工复核"，不得判❌）**：
>   │   模块执行确认净化（依赖细纲中02a生成器字段）、Delta一致性（依赖 chapter_delta + merge-delta.js）、伏笔健康（依赖作者伏笔健康报告）、多线比例（依赖01大纲多线比例表）。
> - **统一兜底规则（与上文"若某项输入缺失"一致）**：任何依赖外部输入的检查项，输入缺失时标"?信息不足"进入人工复核，**禁止因缺失直接判✅或❌**。
> - **外部脚本**（merge-delta.js / extract-used-patterns.js / check-rhythm.js）均为可选自动化工具：有则读取结果辅助判定；无脚本时人工等价判定即可，**不得因"无脚本"而跳过或判❌**。

## 职责边界 — 本技能只做两件事：检测 + 报告

> **负责**：
> - ✅ 检测细纲质量（结构/冲突/钩子/情绪/衔接/一致性/详细度/平台适配...）
> - ✅ 输出质检报告（问题清单 + 证据链 + 评分 + 结论）
>
> **不负责**：
> - ❌ 生成细纲（章节蓝图/字数/衔接包/伏笔表生成都不是本技能的事）
> - ❌ 正文质感/扩写（AI味/感官/精修属于正文阶段，不在此列）
> - ❌ 直接修改细纲内容（发现问题只在报告里标记，由作者修订后复检）
>
> **对输入数据只读不改**：衔接包、伏笔追踪表等一律只读。发现矛盾，在报告中标记并给出修正建议，不做原地修改。

# Part O5: 大纲五检（每卷/每章设计前必答）

> **v4.3 新增**：源自 oh-story-claudecode 的大纲五检体系。在每卷开始设计和每章细纲编写前，必须先回答以下5个问题，从源头保障结构质量。
>
> **本技能用法**：细纲中若已包含"预设答"字段，质检时校验这些回答是否合理；若细纲未包含，则逐问检查其在正文中的落实程度。

```
[大纲五检协议]

每卷设计前必答（本技能验证作者是否已回答）：
├─ ① 本卷交付什么情绪？什么剧情模式能可靠交付？
│   └─ 答不出 → 回01大纲确认该卷定位
├─ ② 本卷核心冲突是什么？
│   └─ 答不出 → 回01大纲确认主线矛盾
├─ ③ 卷节奏（起承转合）哪段加速哪段减速？
│   └─ 高压/推进章占比≥50%且≤70%，低压/过场章≤15%
│   └─ 修炼/信息整理+关系回收章合计≥15%（保证呼吸感，见⑤穷尽口径）
├─ ④ 本卷需要新埋设的伏笔有哪些？上一卷待回收的伏笔如何处理？
│   └─ 与追踪/伏笔.md同步
└─ ⑤ 章节定位分布是否有高低层次（不是全程高压）？
    └─ V6.1.1（数制修正）：卷内每一章必须唯一归入以下穷尽互斥四类之一；"四类合计=100%"改为"四类合计收敛于100%（±5%容差，判定以区间约束为准）"
    └─ 甲·高压/推进章：核心冲突/爽点直推主线（占50%-70%）
    └─ 乙·低压/过场章：喘息/过渡/铺垫（占5%-15%）
    └─ 丙·修炼/信息整理章：成长/世界观注入（占10%-20%）
    └─ 丁·关系回收章：感情/关系闭环（占0%-15%）
    └─ 约束自洽：**丙+丁合计≥15%**（与③"卷节奏"口径一致；丙+丁<15%=缺乏呼吸感，警告）
    └─ 判定：甲类不足50%=节奏过拖；甲类超70%或丙+丁<15%=全程高压疲劳
    └─ 1/4·中点·3/4各锚定一个关键情节

每章细纲前必答（本技能验证作者预答的5+1问）：
├─ ① 本章交付什么情绪？（目标情绪词）
├─ ② 本章核心冲突/爽点是什么？
├─ ③ 本章在卷节奏中处于什么位置？（加速/减速/转折）
├─ ④ 本章需要埋设/回收的伏笔？
├─ ⑤ 本章定位：高压/推进/修炼试错/关系回收/低压生活/信息整理
│   └─ 留空按推进章
│   └─ 高压/推进章配齐钩子+爽点+悬念
│   └─ 低压/关系/修炼/信息整理章允许无显性爽点、弱钩子或仅情绪钩子
│   └─ 底线：每章都给读者一个往下看的理由、相邻章不情绪趋同
└─ ⑥ 用户情绪锚点（V5.1新增）：用户期望读者读完本章后的核心感受？（1-2个词，如"解气/心疼/期待/紧张/震撼"）
    └─ 此字段从01大纲chapter_plan[N].user_emotion_anchor读取，作者不得自行编造；扩写正文时应将其作为情绪工程的首要目标
    └─ 与①目标情绪的关系：①是"角色/叙事交付的情绪"，⑥是"用户期望读者体验的情绪"，两者可能不同
```

> **与既有机制的关系**：大纲五检是产出后具体检查的上游预检——黄金三章硬检查（Part O6.9）、冲突与爽点（质量Gate②）、钩子类型（Part O7）、场景字数（质量Gate⑥）都会在产出后反向验证五检第②/③/⑤答项。五检不通过将触发对应检查项的警告。
>
> **本技能验证规则**：逐章检查作者预答的6问是否完整、合理。缺失任何一问 → 标记"大纲五检不完整"，请作者补充。

# Part O6: 细纲质量Gate（V5.1新增 — 产出后必检）

> **执行时机**：在提供细纲的一章（或一批）内容后执行。
> **与大纲五检的关系**：五检是"设计前预答"（写之前想清楚），质量Gate是"产出后验证"（写完检查是否达标）。
>
> **V5.2.0 说明**：本Gate是本技能的核心质检关卡，原本7项，V5.5.0扩为10项（新增⑧⑨⑩），10项全过才放行。

```
【细纲质量Gate — 每章检查（10项全过才放行）】

① INC章节级检查（至少命中3/13要素）
├─ 新信息/新冲突/新角色面相/新场景/新能力/新关系/新悬念/新反转/新情绪/新代价/新选择/新障碍/新认知
├─ 低压/过场章可降至2项
└─ 命中<2项 → 标记"信息空洞章"，补充内容或合并到相邻章

② 冲突四件套检查（V5.1新增 — 每个核心场景必检）
├─ 目标（Goal）：角色在这场戏里想得到什么？
├─ 障碍（Obstacle）：什么阻止角色达成目标？
├─ 路径（Path）：角色采取什么行动应对障碍？
├─ 代价（Cost）：无论成败，角色付出了/失去了什么？
├─ 四件套缺失任何一项 → 场景缺乏戏剧张力，补充
└─ 过场/信息整理场景可豁免

③ 钩子类型连续性检查（V5.5.0 修正口径 — 与Part O7映射表兼容）
├─ 章末钩子以"招式级"判定重复，不以"类型级"一刀切：
│   ├─ 13种类型可连续出现，但同一类型内的具体招式（手法/落点）3章内不得雷同
│   ├─ 等价操作：把"3章内钩子重复"细化为"3章内同一钩子招式重复"
│   └─ 若仅命中"同类型但招式不同" → 不算重复，通过
├─ 真正判不重复场景：3章内章末用了同一句句式模板/同一落点（如都是"门被推开"收尾）
├─ 记录本章钩子类型+招式到衔接包
└─ 与题材映射联动：作者优先用推荐钩子（≥60%），招式可变，满足两者

④ 情绪连续性检查
├─ 本章目标情绪 → 前一章目标情绪 → 是否相同？
├─ 相同 → 调整本章情绪方向（相邻章情绪不趋同）
└─ 记录本章情绪到衔接包情绪蓝图

⑤ 衔接包完整性检查（V5.2.0 P0/P1分级校验）
├─ P0必须字段检查（缺失=不通过）：
│   ├─ [角色当前状态]（位置/伤势/情绪/持有物/战力等级/生死状态）→ 完整？
│   ├─ [禁止矛盾] → 至少3条？
│   ├─ [数值锁定] → 涉及的关键数值已标注？与number_anchors一致？
│   └─ [角色知识边界] → 在场角色的已知/未知已标注？
│   └─ P0字段缺失任何一项 → 不通过，补全后放行
├─ P1可选字段检查（缺失=警告但不阻断）：
│   ├─ [前章回顾] → 有则检查一致性，无则警告
│   ├─ [必须延续的细节] → 有则检查完整性，无则警告
│   ├─ [状态锁定] → 有跨章状态但未标注 → 警告
│   ├─ [闪回标注] → 含闪回但未标注 → 警告
│   ├─ [本章新增状态] → 有则检查一致性，无则警告
│   ├─ [质感预算] → 有则检查合理性，无则警告
│   ├─ [跨章去重清单] → 有则检查更新，无则警告（注：可由脚本自动生成）
│   └─ P1字段缺失 → 警告但不阻断放行
├─ 模块执行确认检查（V6.1.1 — 依赖02a生成器字段；若细纲本无此字段→标"?信息不足"人工复核，不判❌）：
│   ├─ 逐章细纲末尾"模块执行确认"字段 → 已填写？缺失/敷衍 → 标"?信息不足"→人工复核（不判❌）
│   ├─ 声明的已加载模块 → 含具体模块名（Part G/F2/6等），而非笼统"已加载"？（笼统=警告）
│   ├─ 卷首章/高潮章/首批建纲章 → 必须模块声明"未加载"且无理由 → 警告（建议补理由+影响评估）
│   └─ 未加载模块 → 有理由+影响评估？缺任一 → 警告

⑥ 字数预算合理性检查（V6.1.1 — 单场景字数按平台分层，避免免费站误套付费站单价）
├─ 单场景字数预算（目标总计区间，以 novel_meta.platform 为准）：
│   ├─ 付费站（目标总计 3500-4500）：核心1200-1800 / 重要800-1200 / 过场400-800 / 点缀200-400
│   ├─ 起点/晋江（目标总计 3000-4000）：核心1050-1600 / 重要700-1050 / 过场350-700 / 点缀180-350
│   └─ 番茄免费站（目标总计 2500-3500）：核心900-1300 / 重要550-900 / 过场300-600 / 点缀150-300
├─ 总字数校验：各场景字数求和 → 落入对应平台的目标总计区间即通过
├─ 场景总数是否在3-5个？（免费站建议3-4个，避免场景过碎凑不足字数）
└─ 不符合 → 调整场景分配或场景数量

⑦ 信息释放检查（V5.1新增）
├─ 本章释放的设定信息是否标注了释放方式（对话/旁白/行为/环境）？
├─ 单章新设定释放是否≤3条？（超出=info-dump风险）
├─ 释放的信息是否与00设定一致？
└─ 不通过 → 调整信息释放节奏

⑧ 冲突类型多样性检查（V5.5.0新增）
├─ 本章每个核心场景标注冲突类型：人vs人 / 人vs自然环境 / 人vs自我 / 人vs社会制度
├─ 近3-5章是否至少切换一次冲突类型？（单一"人vs人"连续=读者疲劳）
├─ 近10章是否至少覆盖2类冲突？含"人vs自我"（内心挣扎）为佳
└─ 连续5章均为"人vs人" → 警告并建议插入其他类型冲突

⑨ 情绪健康度检查（V5.5.0新增 — 防"一直爽/一直虐/一直平"）
├─ 近3-5章情绪是否有波峰/波谷交替（非持续同向）？
├─ 压抑/憋屈连续>3章 → 必须插入释放或喘息（研究：压抑超3章弃文率飙升）
├─ 连续5章无情绪波动（纯推进无起伏） → 警告"情绪平淡"
├─ 爽点密集但无任何代价/不确定/喘息 → 警告"一直爽，缺张力"
├─ 与Gate④(相邻不趋同)互补：④看相邻，⑨看连续窗口，两者都过才通过
└─ 记录近5章情绪轨迹到质检报告

⑩ 场景价值变化检查（V5.5.0新增 — 麦基"场景是微型故事"）
├─ 每个核心场景是否让某种价值从正→负 或 负→正（安全/信任/希望/自由/真相…）？
├─ 场景只"发生事件"但价值未变 → 标记"价值不变场景"，评估是否移除/合并
├─ 连续2个以上核心场景均无价值变化 → 警告"情节惯性/原地踏步"
└─ 过场/信息整理场景可豁免，核心场景必检
```

**Gate结果处理（V5.5.0 — 由7项扩为10项）：**

- ⑧⑨⑩中的"警告"级不阻断放行，但与"不通过"分开计（警告计入"需人工复核"档位）

│   └─ 如角色年龄在Ch.1写"19岁"、Ch.3写"21岁"且无时间跳跃 → 矛盾，修正
├─ 扫描最近5章衔接包的[角色当前状态]（P0字段）战力等级，检查是否与 power_system 矩阵一致
│   ├─ 如角色从"凡骨·2枚"突然变成"硬骨·5枚"且无突破情节 → 矛盾，修正

└─ 检查[数值锁定]是否遗漏了已死亡角色的生死状态标注 → 遗漏 → 补充

衔接包链连续性自检 →
├─ 检查衔接包链是否完整连续（无断章/无矛盾状态）
├─ 检查跨章去重清单是否已更新（近3章句式模板+近5章场景元素+章末收尾方式）

# Part I.5质检: 详细度衰减检测

> **执行时机**：每批（3-5章）细纲生成后执行。
> ⚠️ **单位定义**：本检测中的"详细度"= Part I.3详细度评分系统的总分(0-100分)。评分构成：核心场景数(25)+场景完整度(25)+情绪心电图(20)+感官锚点(15)+字数(15)。

```
[详细度衰减检测]

检测方法：
├─ 计算每批的平均详细度
├─ 对比第N批与第1批的详细度
└─ 如果衰减超过阈值，触发警告

衰减检测：
├─ 如果第N批详细度 < 第1批详细度 × 80%：
│   └─ ⚠️ 警告："检测到详细度衰减"
│   └─ 建议：
│       ├─ A. 减少每批章节数（从5章改为3章）
│       ├─ B. 每章生成后暂停，人工确认
│       └─ C. 分天生成（避免一次性生成过多）
│
└─ 如果第N批详细度 < 第1批详细度 × 50%：
    └─ ❌ 严重警告："详细度严重衰减，建议重写本批"
    └─ 可能原因：
        ├─ AI注意力耗尽
        ├─ 约束条件被遗忘
        └─ 上下文窗口不足
```

- 双题材混合（如"都市+悬疑"）→ 取两题材推荐钩子的交集优先，并集次之
- 主题材权重≥70%时 → 以主题材推荐为主
- 用户可覆盖：用户在细纲中指定钩子类型时，优先于映射表推荐

**本技能质检规则（V5.5.0 — 口径与质量Gate③兼容）：**
- 统计作者使用的钩子"类型"占比，推荐类型占比≥60% → 通过
- 推荐类型占比<60% → ⚠️ 警告"钩子类型与题材匹配度不足"
- 钩子重复判定走**招式级**（见质量Gate③）：仅类型相同但招式不同 → 不算重复
- 类型 3 章内连续使用可接受；同一招式 3 章内雷同 → ❌ 不通过
- 题材混合时：双题材取推荐交集优先，主题材≥70%以主题材为主

**钩子术语补全定义（V5.5.0 — 保证本SKILL可独立运行）：**
章末钩子13式：①悬念(未解问题) ②危机(突发危险) ③信息差(一方过早知道) ④反常细节(不对劲) ⑤欲言又止(话没说完) ⑥倒计时(限期) ⑦新角色登场 ⑧物品发现 ⑨预言暗示 ⑩身份揭露 ⑪抉择(两难) ⑫情感反转 ⑬能力升级预告

# Part 10: 质检自我卫门（V5.5.0新增 — 防"假合格报告"）

> **执行时机**：每批质检报告输出后执行。定位：防止长清单一次性执行导致的"每条都填通过"假合格。
> **核心理念**：本模块监控正文的"详细度衰减"，也必须监控自己的质检衰减。

```
【质检自我卫门 — 每批自检】

警戒触发（满足下列任一 → 触发抽样复核）：
├─ 本批所有章节全部"✅通过/放行"，无任何 ⚠/❌/? 项
├─ 本批任一章节的 Gate⑨情绪健康 / ⑩场景价值 连续填"通过"
├─ 本批结论置信度全部为"高"（过高也异常）
└─ 本批检查时长显著短于历史均值（执行过快=跳检）

抽样复核：
├─ 随机抽取本批 20% 章节，对每根检查项做一次"逆向追问"：
│   ├─ 对 Gate①INC：列出本章实际新增信息点 → 是否真有≥2个？
│   ├─ 对 检查项20.5：该伏笔回收前 3章 是否真出现过线索？
│   └─ 对 数值一致性：随机挑 2 个数 > 回原文核实
├─ 逆向追问发现被抽样章节存在漏检 → 全批重跑该检查项
└─ 复核结果写入质检报告"自我卫门"小节

自我衰减检测（对标正文详细度衰减）：
├─ 记录每批质检的"勾选项命中率"（真实不通过+警告 占 检查项总数比例）
├─ 若命中率逐批下降趋势明显（第N批 < 第1批×70%）→ 提示"质检灵敏度衰减"
├─ 建议：拆分检查器执行 / 增加人工抽验 / 更换检查执行顺序
└─ 输出到质检报告，作为本技能自身健康度指标
```
