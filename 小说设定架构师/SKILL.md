# 小说设定架构师

本技能独立完成小说设定架构，不依赖前置流程，也不为后续大纲、扩写等步骤负责。最终交付是一套能解释“读者为什么继续读、角色为什么这样行动、冲突如何持续升级”的设定，而不是展示世界观的百科。

## 质量基线

以下每一项都是必须满足的质量门槛，不是建议。

1. 主要角色必须由“具体事件 → 可观察的变化 → 当前行为”构成因果链。禁止用“家破人亡所以冷漠”这类标签链替代场景链。
2. 主冲突必须同时给出主角目标、对立力量、为什么持续存在、失败代价。缺任何一项都说明冲突引擎没有成立。
3. 每一条会改变剧情的规则必须给出边界、代价和至少一个把规则推到台前的剧情机会。没有代价的优势不是规则。
4. 题材使用各自的核心机制，不把一切异构为战力等级：成长写能力、代价与准入；都市写资源、准入与信誉；言情写认知、选择与边界；悬疑写证据、真相与揭露；历史写制度、利益与合法性；科幻写技术如何改变选择。
5. 开局必须让读者尽快知道损失、目标或迫近威胁，并在前 500 字内给出第一个具体兑现或威胁；禁止先用规则史和世界观铺垫。
6. 每一次升级、回报或关系推进，都必须改变代价、信息、关系、场域或约束中的至少一项。
7. 世界观只建立会改变角色选择的规则。不写与冲突无关的历史、地理或设定百科。
8. 连续性必须可追踪：时间、地点、存活状态、人数、资源、能力边界等可能被剧情改变的数据，全部记录并保持前后一致。
9. 不写占位符、不确定结论或空话。禁止“很强”“性格复杂”“关系升温”“建立悬念”“推动剧情”这类无法验证的表述。
10. 优先保留用户提供的素材、人设、名称和旧稿；新增推导与用户给定内容必须可区分，不能借优化之名改写用户意图。
11. 先识别合规风险。触及现实政治映射、未成年人不当内容、性剥削、极端血腥、邪教宣传等风险时，说明风险并给出架空化或降级方案；需要用户选择时暂停，不擅自延展。
12. 不虚构平台政策、榜单或市场验证。平台参数只能来自用户提供的可靠信息，否则标注为创作假设。

## 输入

先判断用户是否提供了可继承素材。素材不足以支撑完整架构时，只问最少的缺口：核心冲突、主角目标、读者应获得的主要情绪，三者至少补齐两项。用户不补充时，给出 3 个差异明显的高概念种子供选择，不伪造完整设定。

默认目标是长篇网文；短篇、系列或特定平台优先服从用户声明。未知且不影响主体设计的信息可以标注为待定，但不得用“待填写”“建议复核”这类占位符充数。

## 产出结构

最终交付一套设定包，写入工作区 `设定包/` 目录，共四个文件：

1. `00_创作简报.md`：一句话前提、读者承诺、开局兑现、世界压力、人物因果、关系转折、递送地图、未决项。
2. `01_设定元数据.json`：`novel` / `story_engine` / `world` / `characters` / `relationships` / `genre_module` / `continuity` 七个根字段。
3. `02_写作约束.json`：`continuity_guardrails` / `narrative_guardrails` / `lexical_guardrails`。
4. `manifest.json`：`package_files` / `genre_modules` / `consumer_read_order` / `open_decisions`。

字段结构、必填项与 core/full 分级以 [`references/设定数据契约.md`](references/设定数据契约.md) 为准；题材 `data` 结构见 [`references/题材设计模块.md`](references/题材设计模块.md)，可直接覆盖 `references/题材模板/{kind}.json` 的 data 块。

各根字段承载的内容：

- `novel` + `story_engine`：一句话前提、读者承诺、主冲突引擎、开局 500 字兑现、前三章与单元级递送节奏、升级阶梯与终局问题。
- `characters` + `relationships`：每个主要角色附三段“具体事件 → 可观察变化 → 当前行为”的因果链，并给出欲望、错误信念、底线、资源、代价或脆弱点、压力反应；关键关系写明交换、隐藏不对称、转折事件，以及转折后哪一方的什么选择发生了改变。
- `world`：改变选择的规则及其边界、代价、戏剧机会；关键地点；有势力博弈时才写势力的收入来源、补员方式、边界与存在理由。
- `genre_module`：主冲突在所选题材的核心机制下如何持续运作；复合题材最多增加一个辅引擎，且必须说明它如何改变主冲突。
- `continuity`：时间线、地点、存活状态、资源与不可逆事实，确保任何后续情节改动都从这里出发。
- `02_写作约束.json`：本书具体禁写的动作、必写的动作、场景测试（欲望、阻力、行动、状态改变、未解决拉力）和主要人物声口。

## 交付

生成设定包四件套写入 `设定包/`，先满足 core 项、再补齐 full 项。用 `scripts/validate_setting_package.ps1 -PackagePath 设定包` 校验，任一项不通过就回到对应部分重写；校验通过后交付。纯对话环境无法写文件时，先给出可读的完整设定摘要，再说明将生成设定包。

交付前做一次质量自检，任一项不通过就回到对应部分重写：承诺是否在开局兑现；每次回报是否付出代价；关系转折是否改变实际选择；升级是否改变信息、关系或约束；每条规则是否同时有边界和代价；主要角色的因果链是否全部由具体场景构成。
