# 题材设计模块

选择一个主模块。写入 `genre_module.primary = {kind, data, owns_main_conflict: true}`；混合题材只在第二模块确实改变主冲突时启用，写入 `genre_module.secondary = [{kind, data, contribution}]`。辅模块最多一个，且不得与主模块重复。

## 成长/战斗：`progression`

适用于玄幻、修仙、武侠、异能以及以能力升级为主冲突的科幻。`data` 必含：

- `rules`：每条含 `mechanism`、`boundary`、`cost`、`failure_result`。
- `stages`：每阶段含 `name`、`entry_condition`、`new_capability`、`cannot_do`、`maintenance_cost`、`story_pressure`。不要求统一等级数量。
- `cross_stage_exceptions`：非空数组，每项含 `allowed_when`、`price`、`maximum_gap`、`not_allowed_when`。越级必须先有条件再有结果。
- `protagonist_route`：含 `starting_stage`、`milestones`、`blocked_by`，每个里程碑标明要失去或承担什么。

不要把“能做什么”单独当爽点。每次能力增长都要改变主角可承担的风险、可进入的场域或必须支付的代价。

最小填法示例：`rules: [{mechanism:"以体温换火源", boundary:"单次不超过三息", cost:"肢体失温", failure_result:"经脉冻伤三日"}]`，`stages: [{name:"余烬", entry_condition:"残火初觉醒", new_capability:"点燃可燃物", cannot_do:"不能离体燃烧", maintenance_cost:"每日温养", story_pressure:"矿洞唯一热源"}]`

## 都市/现实：`urban`

`data` 必含：

- `resource_topology`：资源节点数组，每项含 `resource`、`controller_id`、`access_gate`、`price`、`story_leverage`。
- `social_positions`：非空数组，每项含 `character_id`、`position`、`available_leverage`、`institutional_boundary`。
- `pressure_system`：对象，说明合同、债务、职业评价、家庭责任、法律/舆论或时间窗口如何迫使行动。
- `mobility_events`：至少 3 个改变资源准入或社会评价的事件，各含 `trigger`、`gain`、`loss`。

不要使用“社会阶层等级”或“能力上限”字段。都市爽点来自资源重组、资格取得、信誉翻转或规则利用，必须标出代价与反制者。

最小填法示例：`resource_topology: [{resource:"客户资料原件", controller_id:"char-lin", access_gate:"办公室签字", price:"抵押住房", story_leverage:"可证清白"}]`

## 言情/情感：`romance`

`data` 必含：

- `core_pair`：对象，含 `a_id`、`b_id`、`current_relation`、`what_each_needs`、`what_each_fears`、`relationship_boundary`。
- `relational_contract`：对象，含 `current_terms`、`benefit`、`avoidance`。
- `beats`：至少 4 项，每项含 `event`、`expectation_broken`、`choice`、`emotional_cost`、`new_relation_state`。
- `external_pressure`：对象，含 `force`、`deadline`、`cost`；不可只靠误会拖延。

关系推进以认知、选择和边界的变化为单位，不使用“暧昧期/热恋期”式等级替代事件。每一次亲近都必须让双方更难维持旧的自我保护方式。

最小填法示例：`core_pair: {a_id:"char-lin", b_id:"char-su", current_relation:"决裂前合伙人", relationship_boundary:"不隐瞒财务"}`，`beats: [{event:"共同核对账本", choice:"公开备份", emotional_cost:"失去客户", new_relation_state:"坦白"}]`

## 悬疑/推理：`mystery`

`data` 必含：

- `case_truth`：真相、行动者、动机、手段、隐藏成本。结局不能依赖此前无法获得的新信息。
- `clue_ledger`：每条含 `id`、`appears_in`、`visible_fact`、`actually_proves`、`who_knows`、`verification_path`、`payoff_in`。
- `false_leads`：每条含 `why_plausible`、`how_disproved`，假线索必须可公平排除。
- `reveal_schedule`：每次揭露含 `question_closed`、`larger_question_opened`、`reader_reinterpretation`。

不要使用“推理阶段/证据数量/认知上限”等伪阶梯。悬疑的升级是旧事实被重新解释、可行动的嫌疑范围缩小、揭露的代价升高。

最小填法示例：`clue_ledger: [{id:"clue-1", visible_fact:"监控显示22:10离开", actually_proves:"不在场证明不成立", who_knows:"char-lin", verification_path:"核对打卡记录", payoff_in:"第3章"}]`

## 历史/架空权谋：`historical`

`data` 必含：

- `institutions`：官职、军权、财政、司法等制度的正式权力与实际权力如何分离。
- `interest_map`：势力各自需要的资源、合法性来源、盟友依赖和不能公开的底线。
- `power_transitions`：升迁、贬谪、夺权、和谈等事件的法理门槛、执行者、收益者和反噬。
- `information_channels`：奏报、商路、宗族、军令等信息传播速度与截断方式。

不要把官阶或势力评级写成战力等级。权谋冲突必须由制度程序、利益结算和合法性共同决定。

最小填法示例：`interest_map: [{faction:"吏部", needs:"举荐权", legitimacy:"铨选制度", secret_line:"不得公开卖官"}]`

## 科幻：`science_fiction`

`data` 必含：

- `technology_constraints`：每项技术的能力、能耗/材料/时间成本、失效边界、社会分配后果。
- `system_dependencies`：基础设施、公司/政体、数据/供应链之间的依赖。
- `human_tradeoffs`：技术便利交换了何种权利、记忆、身体、关系或自治。
- `failure_scenarios`：至少 3 个可进入剧情的故障/滥用情境。

以技术如何改变选择为中心。只有在核心矛盾确实是能力升级时，才额外附加 `progression` 模块。

最小填法示例：`technology_constraints: [{tech:"跃迁引擎", capability:"单次跃迁三光年", cost:"三日充能与舰体过热", boundary:"连续跃迁会偏航", social_cost:"平民无法负担航费"}]`
