# 严谨性与伏笔协议

仅在故事含 P0 人物、重要地点/势力或长线秘密时读取。本文件补充 `设定数据契约.md`，不定义 JSON 根字段，不使用 `power_system`、`number_anchors`、`novel_meta` 等旧接口。

## 人物因果

P0 人物的 `life_chain.events` 必须是可直接写进小说的三个场景。每个场景包含当时的压力、人物做出的选择和留下的可观察变化；随后由 `current_behavior` 连接到开篇中的具体行动。

用三问法检查：

1. 把当前选择倒推回三个事件，因果是否成立？
2. 删除“孤僻、狠厉、善良、天才”等形容词后，仍能否讲清人物会做什么？
3. 人物在压力下的习惯是否会妨碍其目标，从而制造选择？

P1 人物只需一个 `origin_event -> current_behavior` 链。P2 只给一个会在场景里被看见的行为，不为路人编造履历。

## 地点与势力

每个 P0 地点回答：为什么在这里、最稀缺的资源是什么、谁从此处获得收入或权力。三个答案要能共同解释主角为何必须进入或离开该地点。

每个 P0 势力回答：收入从哪里来、成员如何补充、其控制范围到哪里、为什么尚未被更强者取代。将答案写入 `world.factions`，不要另建表格副本。

场景落地时，至少让一个地理、资源或制度条件改变角色的可行选择。无法改变选择的背景信息不进入 P0 设定。

## 连续性

把时间、人物状态、移动限制、稀缺资源和不可违背事实放入 `continuity`。记录“何时改变、因何改变”，而不只记录静态数字。

发现矛盾时按以下顺序处理：

1. 先确认正文是否要产生新的状态变化。
2. 若是，先修改元数据和 `source_revision`，再修改下游约束与正文。
3. 若不是，以元数据为准修正场景，不能用一句补丁旁白掩盖。

## 伏笔生命周期

仅为会改变读者判断或角色选择的秘密建立伏笔。每条伏笔记录在 `continuity.immutable_facts` 或题材模块的专用账本中，并包含：

- `setup`：首次可见的事实和出现位置；不能只写作者知道的真相。
- `misread`：读者/角色当前合理但不完整的理解。
- `pressure`：不回收会造成什么关系、行动或风险变化。
- `payoff`：在哪个冲突中重释此前事实，以及重释后谁必须改变选择。

每次回收都要同时关闭一个问题、打开一个更高层的问题。不能把从未露出的作者设定当作反转，也不能用反复提醒同一线索替代推进。

## 下游检查

细纲为每章交接包写入 `entry_state`、`changed_state`、`unresolved_pull`。扩写只使用该章已获得的信息；精修检查因果是否被解释句替代、伏笔是否可回溯、状态是否已同步到设定包。
