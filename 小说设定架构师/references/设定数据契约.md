# 设定数据契约

本文件定义 `设定包/01_设定元数据.json`、`02_写作约束.json` 与 `manifest.json` 的稳定接口。契约版本为 `1.0`。升级契约时才改变 `contract_version`；单本小说的修订只增加 `source_revision`，不在技能正文中维护版本历史。

## 共同规则

- 三个 JSON 文件都必须含 `contract_version: "1.0"` 和同一个非空 `source_revision`。
- 标识符使用稳定 ASCII slug，例如 `char-lin-yuan`、`loc-old-ferry`；显示名可以是中文。跨文件引用一律使用标识符。
- 未确定且不会阻塞生成的信息不填占位符，写入 `manifest.open_decisions`。会造成错误解释的缺口必须在交付前询问。
- 字符串写可观察事实，不写“很强”“性格复杂”“关系升温”等无条件结论。

## 交付分级

- `core`：首次交付必须通过项，覆盖三文件一致、主角唯一、P0 三段画面、关系关联主角、题材主模块完整、基础连续性存在。
- `full`：严格质量项，在 core 通过后补充，交付以 full 为准。
- 校验器 `validate_setting_package.ps1` 默认跑 full，`--mode core` 仅拦 core 项。

## `01_设定元数据.json`

根对象必须含以下字段：

```json
{
  "contract_version": "1.0",
  "source_revision": "v1.0.0",
  "novel": {},
  "story_engine": {},
  "world": {},
  "characters": [],
  "relationships": [],
  "genre_module": {},
  "continuity": {}
}
```

### `novel` [core]

必填：`title`、`genre`、`premise`、`reader_promise`、`target_platform`、`source_trace`。

`source_trace` 是数组，每项含 `subject`、`origin`（`user` 或 `derived`）与 `note`。

### `story_engine` [core: opening_delivery, reward_map, three_chapter_map, main_conflict; full: escalation_ladder, ending_question]

- `opening_delivery` [core]：`reader_knows`、`immediate_conflict`、`first_payoff_or_threat`。
- `reward_map` [core]：`core_reward`、`first_500`、`first_3_chapters`、`unit_loop`、`cadence`、`price_of_reward`。`first_500` 和 `first_3_chapters` 必须是可写场景，不得只写“建立悬念”；`cadence` 写 `editorial_assumption: ...`，不得伪造平台事实。
- `three_chapter_map` [core]：恰好 3 项，各含 `chapter`、`change`、`reader_delivery`、`ending_pull`。
- `main_conflict` [core]：`protagonist_goal`、`opposing_force`、`why_it_persists`、`failure_cost`。
- `escalation_ladder` [full]：至少 3 项，各含 `trigger`、`what_changes`、`price`，且升级不可以只是敌人数字变大。
- `ending_question` [full]：非空文本。

### `world`

- `rules` [core]：至少 1 条，每条含 `rule`、`boundary`、`cost`、`dramatic_use`。
- `locations` [core]：至少 1 个；P0 含 `id`、`name`、`importance: "P0"`、`geography`、`resource`、`economy`；P1/P2 至少含 `id`、`name`、`importance`、`story_use`。
- `factions` [full]：可为空数组；P0 需含 `income`、`recruitment`、`boundary`、`reason_to_exist`。

### `characters` [core]

每项必填：`id`、`name`、`priority`、`role`、`current_goal`、`misbelief`、`line_in_the_sand`、`resources`、`cost_or_vulnerability`、`pressure_tell`、`status`。

- P0 额外必填 `naming_rationale` 与 `life_chain`。`life_chain` 必含 3 个 `events`（各含 `scene`、`observable_change`）及 `current_behavior`；事件必须是画面，不得是“被遗弃”“家族覆灭”等标签。
- P1 必含 `origin_event` 和 `current_behavior`。
- `status` 仅 `alive`/`dead`；`dead` 必须有 `death_time` 与 `death_cause`，并在 `continuity.immutable_facts` 说明例外。

### `relationships` [core]

至少 1 项，每项含 `a_id`、`b_id`、`current_exchange`、`hidden_asymmetry`、`turning_event`、`after_turn_state`、`scene_opportunity`。至少一项关联主角，并在主线中改变选择。

### `genre_module` [core: primary 完整，secondary 只需 kind/contribution; full: secondary data 完整]

必填 `primary` 与 `secondary`。`primary` 含 `kind`、`data`、`owns_main_conflict: true`；`secondary` 是 0-1 项数组，core 阶段只要求 `kind`、`contribution`，full 阶段再补与模板一致的 `data`。`kind` 限 `progression`/`urban`/`romance`/`mystery`/`historical`/`science_fiction`，辅模块不得与主模块重复。`data` 结构见 `references/题材设计模块.md`，可直接覆盖 `references/题材模板/{kind}.json` 的 data 块。禁止 `alternative_module`/`tier_name`/`ability_ceiling` 等旧字段。

### `continuity`

- `timeline` [core]：至少 1 项，每项含 `time`、`event`、`consequence`。
- `character_states` [core]：键为角色 `id`，值含 `status` 与 `current_position`。
- `location_travel` [full]：数组可为空，但每项必须含 `from_id`、`to_id`、`method`、`duration`、`constraint`，且 id 必须存在。
- `scarce_resources` [full]：数组可为空。
- `immutable_facts` [full]：数组可为空。

## `02_写作约束.json`

根对象必填：`contract_version`、`source_revision`、`continuity_guardrails`、`narrative_guardrails`、`lexical_guardrails`。

- `continuity_guardrails` [core]：至少 1 条硬事实。
- `narrative_guardrails` [core: avoid_moves, required_moves, scene_test; full: reveal_policy, relationship_policy]：`avoid_moves`/`required_moves` 非空数组，`scene_test` 含 `desire`/`obstacle`/`action`/`changed_state`/`unresolved_pull`。必须按本书重写为具体规则，不可抄描述句。填空句式：`avoid_moves: ["不在{具体冲突}前用整段解释{具体规则名}"]`。
- `lexical_guardrails` [core: avoid, prefer; full: character_voice 按 P0 逐人]。

## `manifest.json`

必填：`contract_version`、`source_revision`、`package_files`、`genre_modules`、`consumer_read_order`、`open_decisions`。

`package_files` 必须列出四个交付文件。`consumer_read_order` 对 `outline`/`beat_sheet`/`draft`/`revision` 分别指定读取顺序，且后三者第一步都是 `02_写作约束.json`，第二步为 `01_设定元数据.json`。
