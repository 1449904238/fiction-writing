# 题材路由与质量门槛

本文件只在 `genre_profile.primary` 确定后读取。它不是题材公式，而是决定“什么算推进、什么算偷懒”的路由表。辅题材最多承担一个次要推进轴，不能覆盖主冲突。

| 主类型 | 主要推进轴 | 必须交付 | 禁止用来代替推进 | 规则 ID |
|---|---|---|---|---|
| `mystery` 悬疑 | 证据、认知、风险 | 新证据改变嫌疑模型；揭示前有可回溯依据；揭示后改变选择 | 为保谜底隐瞒角色本应知道的事实 | MYST-01～04 / A1 A2 |
| `romance` 言情 | 边界、信任、共同目标 | 关系因选择和代价改变；双方都有主动欲望。ROMA-01 的"关系轴"仅指边界/信任两个纯关系轴，共同目标/失去风险/欲望张力算情境轴——只有情境轴推进的言情等于没有关系变化 | 反复误会、偶遇和标签式心动 | ROMA-01 / A1 A2 |
| `progression` 成长/战斗 | 能力边界、资源、战术、代价 | 新能力必须在验证场景中解决新问题并带来新限制 | 只增数字、无代价突破 | PROG-01 02 / A1 |
| `workplace` 职场/现实 | 准入、制度、利益、声誉 | 专业规则改变角色能做的选择；利益冲突可追溯 | 把职业术语当装饰背景 | WORK-01 / A1 |
| `historical` 历史/架空 | 制度、资源、地理、身份 | 时代限制进入角色选择；资源分配产生真实代价 | 现代价值观无成本碾压环境 | HIST-01 / A1 |
| `urban` 都市 | 现实压力、关系、资源、声誉 | 生活约束与主线互相施压；回报改变责任 | 万能人脉、偶然巧合解决核心问题 | URBA-01 / A1 |
| `science_fiction` 科幻 | 科技规则、伦理、系统性后果 | 核心设定至少一次改变可行选择并承担后果 | 只换名词的现代都市冲突 | SCIF-01 / A1 |
| `fantasy` 奇幻 | 世界规则、身份、资源、阵营 | 世界规则成为行动阻力；阵营选择有代价 | 百科式设定倾倒 | FANT-01 / A1 |
| `literary` 严肃文学 | 价值冲突、关系、认知 | 行动与潜文本共同改变人物关系或自我理解 | 用抽象抒情替代事件选择 | LITE-01 / A1 |

## 机器契约映射（contract 1.3）

本表有一条机器可执行的孪生版本：`references/genre_contracts.json`。上表“规则 ID”列与该文件中的规则逐条对应：

- 无后缀 ID（如 `MYST-01`）是**结构规则**：`severity=block` 的只检查无歧义的结构事实（词表命中、时序、ID 引用），校验器直接拒绝；`severity=warn` 的在回执中告警。
- `A` 系 ID（如 `MYST-A1`）是**避免动作检测器**：全部为 `severity=warn`，命中后写入审计回执并路由给语义评审抽查，不直接拒绝。质量判断不交给正则，正则只负责把可疑段落捞出来。
- `scope=volume` 的规则只在「该卷全部章节都出现在本次大纲内」时执行（batch 大纲只覆盖半卷时跳过，避免用残缺数据误判）；`scope=chapter/outline` 的规则始终执行。

修改推进轴词表时必须同步更新本表和 `genre_contracts.json` 两处；两处不一致以 `genre_contracts.json` 为准（它是校验器的实际数据源）。

## 路由执行

1. 先写 `genre_profile`，再写 `story_engine`；不允许先生成通用情节再贴题材标签。
2. 每章至少有一个 `progression_axes` 对应的状态变化；没有时必须标注为休整章，并说明它兑现了哪项 `must_deliver`。
3. 盲评按主类型分组。总平均通过不能掩盖某一题材低于门槛。
4. 混合题材按主类型评审；辅题材只检查是否服务主冲突，不按两套规则叠加扣分。
