# 大纲数据契约

`01_大纲数据.json` 是大纲阶段的唯一机器权威。人类可读简报与 02 交接稿都必须从它投影，不能反向覆盖它。机器结构以同目录 `outline.schema.json` 为形状基线，语义规则由 `scripts/validate_outline.py` 执行。

契约分两个版本：`1.2` 是现行基础契约（上文全部规则）；`1.3` 在其上叠加题材契约、实体账本、商业层与跨批承接断言（见文末「Contract 1.3 扩展」）。旧 `1.2` 大纲仍按 `1.2` 路径校验，互不破坏；新生成的大纲应声明 `1.3`。

## 根对象

```json
{
  "contract_version": "1.2",
  "outline_scope": "batch",
  "source_revision": "v1.0.0",
  "source_package_revision": null,
  "source_trace": {"preserved": [], "inferred": [], "document": "设定文档.md"},
  "input_package": null,
  "setting_refs": {"character_ids": [], "location_ids": [], "faction_ids": [], "rule_ids": [], "resource_ids": []},
  "genre_profile": {"primary": "mystery", "secondary": [], "reader_promise": "", "progression_axes": [], "must_deliver": [], "avoid_moves": []},
  "story_threads": [],
  "direction_gate": {},
  "story_engine": {},
  "narrative_lines": [],
  "volumes": [],
  "chapters": [],
  "foreshadowing": [],
  "branch_nodes": [],
  "open_decisions": []
}
```

必填字段不得使用 `待定`、`TODO`、`[填写]` 一类占位符。只有 `open_decisions` 可记录未知项，每项必须含 `question`、`blocks`、`owner`。

`source_package_revision` 与 `input_package` 只在输入是 `设定包/`（`manifest.json` + `01_设定元数据.json` + `02_写作约束.json`）时才填写，此时两者 `source_revision` 必须一致且不得被静默改写。独立输入是一份 `_设定架构.md` 样式的设定文档时，这两个字段省略或为 `null`，`source_trace.document` 记录来源文档，从文档原样保留的设定进 `source_trace.preserved`，自行推导的进 `source_trace.inferred`。

## 必填结构

| 对象 | 必填字段 | 规则 |
|---|---|---|
| `direction_gate` | `premise`, `reader_promise`, `pitch`, `opening_delivery`, `assumptions` | `opening_delivery` 含 `first_500` 与 `first_3_chapters` |
| `story_engine` | `theme_question`, `protagonist`, `opponent`, `ending_proof`, `escalation_ladder` | 梯子至少 3 项，每项含 `trigger`, `choice`, `cost`, `state_change` |
| `narrative_lines[]` | `id`, `name`, `type`, `purpose` | `id` 格式 `L-XXX`；`type` 为 `main`、`subplot`、`relationship`、`growth` 之一 |
| `volumes[]` | `id`, `chapter_start`, `chapter_end`, `promise`, `goal`, `opposition`, `choice`, `cost`, `state_change`, `anchors`, `resolution_id` | `id` 格式 `V-XX`；锚点含 `quarter`, `midpoint`, `three_quarter`, `ending`；`resolution_id` 是稳定终局/卷末证明 ID |
| `chapters[]` | `id`, `volume_id`, `number`, `purpose`, `reader_emotion`, `emotion_source`, `rhythm_function`, `narrative_line_ids`, `anchor_tags`, `gocs`, `scene_effects`, `foreshadowing_ops`, `state_delta`, `thread_ops`, `continue_reason` | `id` 格式 `CH-XXXX`；`state_delta` 是跨章连续性账本的最小记录；`emotion_source` 为 `user` 或 `editorial_assumption` |
| `foreshadowing[]` | `id`, `summary`, `type`, `importance`, `plant_chapter`, `planned_harvest`, `harvest_effect`, `status` | `id` 格式 `FS-XXX`；状态为 `PLANT`、`ADVANCE`、`HINT`、`REAP`、`ARCHIVE`；`planned_harvest` 必须为空或真实章节 ID |
| `branch_nodes[]` | `id`, `chapter_id`, `type`, `decision`, `selected`, `alternatives`, `selection_reason` | `id` 格式 `BN-XX-XX`；`selected` 含 `beats`, `short_term`, `mid_term`, `long_term`, `risks` |

`gocs` 至少一项；每项含 `goal`、`obstacle`、`choice`、`state_change`。`scene_effects` 至少一项；每项含 `scene_id`、`reader_reaction`、`reader_question`。`anchor_tags` 为零或多个卷锚点功能；每卷至少一章含该卷 `anchors.ending`。`foreshadowing_ops` 可以为空数组。

`genre_profile` 决定题材质量门槛，具体路由见 [题材路由.md](题材路由.md)。`story_threads` 是跨卷故事线账本；每条线必须从 `open` 开始，最终 `close` 或 `abandon`。`outline_scope=batch` 允许未闭合故事线和非终局卷；`outline_scope=full` 才要求全书终局及所有故事线闭合。

## 跨对象规则

- `chapters.number` 必须从 1 连续递增，且每章恰好落入一个卷的章节区间。
- 当声明了 `input_package` 时，`source_package_revision` 必须与其 `source_revision` 一致；`input_package.contract_version` 记录上游设定包版本，不得被静默改写。
- `setting_refs` 中的角色、地点、势力、规则和资源 ID 必须是来自上游设定包的严格 ID；独立设定文档输入没有稳定 ID 时保留空数组，并把对应设定锚点记入 `source_trace.preserved`，不伪造机器 ID。
- `chapters.volume_id`、`narrative_line_ids`、`foreshadowing_ops[].id`、`branch_nodes.chapter_id` 必须引用存在的 ID。
- 每卷必须至少有一章包含该卷的 `ending` 功能；仅当 `outline_scope=full` 时，终卷的 `resolution_id` 才必须与 `story_engine.ending_proof` 一致。
- 每章可有多条叙事线。线权重按 `chapters[].line_weights` 的场景/节拍权重统计；若未提供权重，校验器只验证引用和交汇记录，不声称百分比准确。
- `foreshadowing_ops[].action` 只能为 `plant`、`advance`、`hint`、`reap`、`archive`，并与伏笔的时间顺序一致。
- `planned_harvest` 存在时必须不早于 `plant_chapter`；`actual_harvest` 存在时必须不早于埋设且与 `reap` 操作章节一致。
- `line_weights` 若存在，键必须覆盖本章 `narrative_line_ids`，值非负且总和为 1（允许 1e-6 误差）；多线章需有 `line_intersection`，且交汇章不得重复计权。
- `story_engine.ending_proof.resolution_id` 必须等于终卷 `resolution_id`，终卷 `anchors.ending` 只能引用同一终局证明语义。
- `chapters[].state_delta` 必须写明入口状态、触发、选择、代价、变化、新义务和未解决拉力；`thread_ops` 必须与 `story_threads` 的生命周期一致。
- 相邻章节默认至少共享一项连续性状态；若确有时间跳跃、视角切换或状态重置，使用 `state_delta.continuity_break=true` 并填写原因。
- 任何被标为“市场事实”的结论必须包含 `evidence_source`；没有证据时改为 `editorial_assumption`。

## 内部投影（可选）

存在下游消费者时才交付 `02_细纲交接`，从 `chapters[]` 投影所需字段：

| 02 所需字段 | JSON 来源 |
|---|---|
| `chapter_plan[N].user_emotion_anchor` | `reader_emotion`，并附 `emotion_source` |
| `scene_effect_target` | `scene_effects` |
| 叙事线归属 / 连续计数 / 交汇 | `narrative_line_ids`、`line_weights`、`line_intersection` |
| 分支推演参考 | 命中章节的 `branch_nodes[].selected.beats` |
| 伏笔操作 | `foreshadowing_ops`，保留 `FS-XXX` ID |

旧消费者要求单一线归属时，选择该章权重最大的线，并在交接稿中保留其余交汇线；不得把多线章伪造为没有交汇的单线章。

## Contract 1.3 扩展

以下断言只在 `contract_version = "1.3"` 时启用。分级门禁原则：`block` 只检查无歧义的结构事实（词表命中、时序、ID 引用、文件存在性），校验器直接拒绝；`warn` 检测质量型负模式，写入审计回执并路由给语义评审（[judge_protocol.md](judge_protocol.md)）抽查，不直接拒绝——防止为过审而贴空壳标签。

### 题材推进轴（axis_advance）

- `genre_profile.progression_axes` 与每章 `chapters[].axis_advance[].axis` 必须落在 [genre_contracts.json](genre_contracts.json) 为该题材定义的词表内（加上 `休整`）。
- 每章至少 1 条 `axis_advance`；休整章用 `axis=休整` 且 `delivers` 必须逐字兑现一条 `must_deliver`。
- `cost_paid` 缺失不拒绝，但逐条告警转语义评审。`evidence` 若填写必须形如 `CH-0002#gocs[0].state_change`，且章节 ID 真实存在。
- 各题材的结构规则与避免动作检测器（`MYST-01`…`LITE-A1`）的机器定义全部在 `genre_contracts.json`，散文版见 [题材路由.md](题材路由.md)。

### 实体账本与内部锚点

- `entity_ledger.entities[]`：每个关键实体（角色/物品/地点）按章记录 `critical_facts`（chapter/fact/status/evidence），用于检测"死亡实体后续参与"与数值跳变。状态终态（dead/destroyed 等）的实体不得再作为本章 `state_delta.changed_state` 或 `gocs.state_change` 的参与者；回忆性内容须显式标记 `flashback`。
- `internal_anchors`：独立模式（无上游设定包）下自建的能力/数值锚点，结构与设定包字段同构，避免数值漂移。

### 商业层（commercial_profile）

- `platform`：目标平台。
- `assumption_flag`：`editorial_assumption`（无对标数据时的诚实声明）或 `benchmarked`。
- `benchmarked` 时必须提供 `evidence_source` 指向真实存在的对标节奏包文件；文件不存在直接 INVALID，禁止虚构来源。
- `hook_policy.first_3_chapters = all_high_pull` 时，前三章 `continue_reason.hook_type` 必须全部属于高拉力集合（危机/悬念/反转）。
- `continue_reason` 可用结构化形式 `{hook_type, text}`；`hook_type` 是封闭枚举：危机/悬念/反转/期待/情感/兑现/代价。

### 跨批承接（chapter_offset / inherited）

- `chapter_offset`：本批第一章对应的全书绝对章号 - 1。本批内章节号仍需从 `offset+1` 连续递增。
- `inherited.threads / inherited.foreshadowing`：声明从上一批延续的线程与伏笔 ID。承接对象的 `opened_chapter`/`plant_chapter` 允许指向本批之外（历史事实），但本批内不得重复 open/plant。
- 合法性由 `scripts/finalize_outline.py --previous <上一批输出目录>` 跨批核验兜底：章节衔接（本批 offset 必须等于上一批结束章号）、承接对象真实存在、伏笔终态兼容（已 REAP 的不能续写）、实体终态兼容（已销毁的不能再现）、契约版本不得从 1.3 降级回 1.2。

### 短篇档位（outline_profile）

- `outline_profile=lite` 仅允许 `outline_scope=batch` 且必须配 `profile_intent`（短篇意图说明），放宽 `story_threads`/`thread_ops`/`volumes` 记账；`gocs`/`scene_effects`/`axis_advance` 三项任何档位都不放宽。

### 设定包 → 大纲 字段映射（消费 `设定包/` 输入时）

输入是设定架构师产出的 `设定包/`（`manifest.json` + `00_创作简报.md` + `01_设定元数据.json` + `02_写作约束.json` + 可选 `.work/core_gate.json`）时，按下表忠实转换。映射是**必须的传递**，不是可选的参考；validator 会在这些点上做 block/warn 级机检（需透传 `--setting-package` 目录）。

| 设定源 | 大纲目标 | 机检 |
|---|---|---|
| `00_创作简报.md`：读者承诺、递送地图 | `direction_gate.reader_promise`、`direction_gate.opening_delivery` | — |
| `.work/core_gate.json`：direction/premise/first_3_chapter_change/continuity_anchor | `direction_gate.premise/pitch/opening_delivery`、`story_engine.continuity_anchor` | — |
| `01.novel.reader_promise` | `genre_profile.reader_promise` | — |
| `01.story_engine.three_chapter_map / reward_map / escalation_ladder` | 前三章 `chapters`、`volumes[]`、`story_engine.escalation_ladder` | — |
| `01.world.rules[].id` / locations / factions / resources | `setting_refs.{rule/location/faction/resource}_ids` | `block`：ID 必须真实存在 |
| `01.characters[].id` / relationships | `setting_refs.character_ids`、`story_engine.protagonist/opponent`、叙事线 | `block`：ID 必须真实存在 |
| `01.genre_module.primary.data.clue_ledger[].id` | 每章 `foreshadowing_ops` + `foreshadowing[].source_clue` 绑定同一 clue | `block`：`source_clue` 引用的 clue id 必须存在于 clue_ledger |
| `01.genre_module.primary.data.case_truth / reveal_schedule / false_leads` | `story_engine.ending_proof`、揭示节奏、`foreshadowing` 形态与收获效果 | — |
| `02.narrative_guardrails.avoid_moves` | `genre_profile.avoid_moves`（逐条传递） | `warn`：缺失/改写到无法匹配则告警，转语义评审 |
| `02.narrative_guardrails.required_moves` | `genre_profile.must_deliver`（逐条传递） | `warn`：同上 |
| `02.narrative_guardrails.scene_test`(desire/obstacle/action/changed_state/unresolved_pull) | 卷/章 `gocs`、`state_delta` 的 goal/obstacle/choice/changed_state/unresolved_pull | — |
| `02.narrative_guardrails.reveal_policy / relationship_policy` | `genre_profile.must_deliver` 的补充条目 | — |
| `02.lexical_guardrails.avoid / character_voice` | 正文阶段引用；不在大纲结构内强制 | — |

**约束传递的措辞宽容**：设定包措辞是大纲各项的语义来源，允许改写措辞但不允许丢失语义（见 `_shares_core` 的公共子串匹配）。传递失败的条目以 `warn` 写入审计回执，交由语义评审逐条裁决，不直接拒绝。
